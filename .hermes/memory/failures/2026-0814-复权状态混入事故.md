## 事故链条

1. **三个数据源复权状态不一致**：
   - 腾讯 adapter 名义 qfq（`fqkline/get+qfq`），实际取 `day`（不复权）→ 混入原始价
   - 新浪 getKLineData → 原始价
   - akshare `stock_zh_a_hist(adjust="qfq")` → 前复权价
   - 三者混入同一个 `daily_price_latest.parquet` → 同一列价格不同复权基准

2. **ETL 复权层被跳过**：`full_pipeline` 传 `adj_factors=None`，本应在 Stage4 做的复权标准化没执行

3. **validation gate 缺涨跌停检查**：无法拦截异常价格跳变

4. **叠加腾讯 fqkline 负价格 bug**：600438 2018-10 段返回 `close=1.172`（真实 6.43），
   甚至出现负价格 → `close=0.002 → fwd5=21624x` 的荒谬收益

## 影响

- fwd return 计算被污染（close 相除被除权/坏价跳变打爆）
- 8/12 之前的历史研究（momentum_vol_full）Q1-Q5 绝对收益水平不可信
- IC 方向（秩相关）仍可靠 — 反转 Alpha 等方向性结论不受影响

## 修复（commit 80f0160 / 828c774 / b76ea66）

1. **统一策略**：全库使用**不复权原始价**（三源均提供原始价，原始价是本源）
2. **腾讯弃用 fqkline**：改用 `kline/kline` 无复权参数取原始价（BANNED 标记 + 单测守卫）
3. **复权因子表独立存储**：`data/dataset/adj_factor.parquet`（akshare qfq-factor，3051 只/47961 行）
   - 公式实测：`close_qfq = close_raw / qfq_factor`（最新除权日 factor=1.0，越早越大）
   - 计算层按需复权，不混入价格表
4. **腾讯唯一数据源**（用户决策）：删新浪/akshare fallback；`--source=sina` 直接 FAILED；
   网络故障率 >5% 抛错退出；退市股（day 空数组）正常跳过不计数
5. **涨跌停 gate**：|单日收益|>21% 拦截（增量场景；全历史需结合因子表区分除权日）
6. **列名标准化**：腾讯返回中文列（日期/开盘/收盘），统一用 `CleaningEngine.COLUMN_MAP` 转换
