# QT 收益归因：调仓日有买入信号，为什么 3 个月只赚 0.41%

- 分析日期：2026-11-08
- 数据区间：2026-08-16 → 2026-11-06（54 个交易日，60 个决策包）
- 账户：初始 ¥100,000 → 权益 ¥100,413（**+0.41%**；已实现 +413，浮动 +0）
- 性质：只读分析，未改动任何生产代码
- 结论置信度：核心结论 FACT（公式已逐笔验算匹配），收益外推部分标注 INFERENCE

---

## 一、结论先行

**不是选股不赚钱，是钱基本没进场。** 三个月平均仓位 **2.40%**（中位数 0.90%），
策略在同一时期的满仓口径能赚 +8.99%（paper 对照），市场同期 -6.99%。

收益被稀释的直接原因：**「单票 8% 上限」被错误地乘在了已经打过 regime 折扣的
`alloc_capital` 上，等于对仓位做了第二次折扣** —— 熊市 10% 敞口 × 单票 8% = 总资产
0.8%/只，3 只合计 2.4%，与实测平均仓位 2.40% 精确吻合。

## 二、事实（FACT，全部本次实跑）

### F1 实际仓位暴露极低

`data/simulation/shadow_daily.parquet`（跟决策包走，等同实盘节奏），47 个交易日：

| 指标 | 值 |
|---|---|
| 平均仓位（market_value / total_equity） | **2.40%** |
| 中位数 | 0.90% |
| 仓位 >1% 的天数 | 17 / 47 |
| 唯一一次高仓位 | 2026-08-16 24.68%（首日，当日即平） |
| 权益 | 100,000 → 100,407（**+0.407%**） |

### F2 策略本身在同期是赚钱的（满仓口径对照）

`data/paper_trading/*.json`（PaperTradingTracker 跟策略原始信号、不加风控、
不按 regime 缩放，8-21 → 10-14 共 30 个调仓周期）：

| 策略 | paper 收益 | 同期全市场等权 | 超额 |
|---|---|---|---|
| `lvr_vol_only`（当前生产） | **+8.99%**（Sharpe 1.58 / MaxDD 14.6%） | -1.30% | **+10.3pp** |
| `momentum_vol_full` | +1.61%（Sharpe 0.60 / MaxDD 8.5%） | -1.30% | +2.9pp |

同期等权全市场（`daily_price_latest` 全市场日收益均值累乘）：
- 2026-08-21 → 10-14：**-1.30%**
- 2026-08-16 → 11-06：**-6.99%**
- 2026-10-08 → 11-06：**-6.90%**

⇒ **市场在跌，策略满仓能赚 9%。实盘只赚 0.4%，差额全部来自仓位，不是选股。**

### F3 「8% 单票上限」作用在了错误的基数上（根因，已逐笔验算）

链路（`qp/pipeline/daily_pipeline.py`）：

1. `alloc_capital = total_capital × suggested_position_pct × strategy_exposure_scale`
   → 熊市 `suggested_exposure = 0.1`：**alloc_capital = 100,000 × 0.1 = 10,000**
2. 候选表里硬编码 `max_weight_limit = 0.08`（`pl.lit(0.08).alias("max_weight_limit")`）
3. `CapitalAllocator` / `weight_normalizer` 把每只权重 clip 到 **8%**
4. 下单金额 = `target_weight × alloc_capital` = **8% × 10,000 = 800 元/只**
5. 300 元～800 元 ÷ 股价 → 整手取整 → 常见结果 0 股（股价 >8 元的票直接买不进）

逐笔验算（预测股数用 `800 / price // 100 * 100`，与实际决策包 100% 命中）：

| 决策包 | alloc | target_wt | 目标金额 | 实际成交 | report.total_invested |
|---|---|---|---|---|---|
| dp-2026-11-04 | 10,000 | 8.00% | 800/只 | 601916 200股×2.96=592；601005 600股×1.17=702；603167 0股 | 1,294 ✓ |
| dp-2026-11-05 | 10,000 | 8.00% | 800/只 | 600168 100股×4.33=433；601916 200股×2.93=586；603167 0股 | 1,019 ✓ |
| dp-2026-10-08 | 10,000 | 8.00% | 800/只 | 601158 100股×4.04=404；603167 100股×8.00=800；601033 0股 | 1,204 ✓ |
| dp-2026-09-01 | 10,000 | 16.67% | 1,667/只 | 002608/600207/600930 整手后 1,438/1,344/1,572 | 4,354 ✓ |

**口径冲突的证据**（同一份代码里两种定义并存）：
- `qp/decision/engine.py` 的 `generate_recommendations` 注释：8% 单仓上限**按总资产口径**判断，
  用 `alloc_capital_ratio = total_capital / portfolio_capital` 换算，避免 bear 市假警告
  ⇒ `target_wt` 被定义为「相对 `alloc_capital`」
- `qp/portfolio/risk_manager.py` 的 `evaluate` 注释：`weight_scale` 让等权权重
  「matches the allocator's actual execution（如 sideways_down 30% 敞口 → 1/5 × 0.3 = 6% < 8% cap）」
  ⇒ `position_weights` 已经是「占总资产」口径（6% 就是总资产 6%）

两条路径对同一个「8%」的理解相反，执行路径（CapitalAllocator）取的是前者但基数用了后者
的结果，于是总资产 8% 退化成 0.8%。

## 三、归因拆解（收益 = 选股 × 仓位）

用线性近似把 +0.407% 拆开（INFERENCE，非精确分解）：

```
满仓口径（paper 对照）        +8.99%
平均仓位系数                  2.40%  →  +8.99% × 2.40% ≈ +0.22%
实际                         +0.41%
```

差额的主要构成：
1. **仓位系数 2.4%（占绝大部分）** —— F1/F3
2. 8-16 那天 24.68% 仓位的短时暴露贡献了正收益，抬高了均值（F1）
3. 交易成本与整手取整损耗（qty=0 的票反复错失）

⚠️ 反过来看也要说清：正因为仓位低，市场跌 6.99% 时账户只跌 0.1%，
**「跑赢市场 7.4pp」里主要是空仓带来的 beta 规避，而不是 alpha**。
把「跑赢」当成「策略有效」是归因陷阱。

## 四、主要矛盾

> 系统用「beta 择时」的敞口逻辑，去管理一个「熊市避险 alpha」策略。

- `REGIME_POSITION_MAP` 的语义是 beta 仓位管理：bear → 10% 敞口。市场跌，减仓，这是对通用策略合理的。
- `lvr_vol_only` 的因子是 `Volatility_20D`（低波动），经济含义是**下跌市里更抗跌**。
  它的 alpha 恰恰在 bear 期间最强 —— paper 对照 +8.99% vs 市场 -1.30% 就发生在 bear 期间。
- 结果：系统在最该持仓的市场状态里把仓位压到 2.4%，等于**用对冲逻辑跑掉了 alpha 策略的收益来源**。

这是设计层面的矛盾，不是代码 bug。**F3 是 bug（可以修），这一条是策略/风控的取舍（需要决策）。**

## 五、修复方案（未实施，等批准）

### 方案 A：修正 8% 上限口径（技术 bug，确定性最高）

- 位置：`qp/pipeline/daily_pipeline.py` 的候选表构造（`max_weight_limit` 硬编码 0.08）
- 改法：`max_weight_limit = min(1.0, 0.08 / (alloc_capital / total_capital))`，
  让「8%」始终按总资产口径解读；`alloc_capital` 本身仍是硬性总额约束
- 效果（F4）：10% 敞口下 3 只从 2.4% → 10%；30% 敞口从 7.2% → 24%
- 风险：放大约 4 倍仓位；**生产敏感路径**，需先跑回归（`tests/unit/test_pipeline_critical_path.py`、
  `test_portfolio*.py`）+ 影子盘回放对比再上线
- 需要同步的假设：`risk_manager.evaluate` 的 `weight_scale` 语义注释、
  `engine.generate_recommendations` 的 `alloc_capital_ratio` 换算，两处口径必须统一

### 方案 B：regime 敞口与策略特性解耦（设计层，影响更大）

- 思路：`suggested_exposure` 的来源从「市场 regime」改为「该策略在该 regime 下的历史表现」
  （策略级 regime 表），必要时允许 bear 下 100% 敞口
- 证据基础：paper 对照 + `lvr_vol_only` 因子方向是低波避险
- 风险：30 天 paper 样本太小；需要 walk-forward 验证「低波策略在 bear 超额」是否稳定，
  否则容易变成对最近一段行情的事后拟合
- 建议：先做研究（不改生产），用 2019-2026 分 regime 统计该策略超额

### 方案 C：调仓节奏与整手损耗（小改进）

- 现状：每股 300～800 元目标金额，股价 >8 元直接买不进（F3 表里多次 qty=0）
- 若 A/B 任一落地，此问题自动缓解；单独修的话可考虑「目标金额不足 1 手时整单跳过并记录」，
  避免决策包里出现 0 股的 BUY 建议

### 推荐顺序

**A 先修**（纯口径 bug，证据闭环，不涉及策略判断）；**B 只做研究不动生产**；
C 随 A 一起消失。A 上线后观察 1-2 个调仓周期的实际仓位与 slippage 再评估 B。
