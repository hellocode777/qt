# 调仓节奏（cadence）扫描：40 天已是最优，80 天是高方差幻觉

**日期**：2026-11-08
**背景**：收益归因（`qt_return_attribution_2026-11.md`）结论是「仓位口径是 bug，但收益天花板在熊市 10% 敞口」。
其中一条候选出路是「调仓节奏 40 交易日太长，一年只有 6 次机会」——本文档验证它。
**结论**：**不成立，不建议改 cadence。40 天保持不变。**

---

## 一、结论先行

| cadence | Sharpe 均值 | 标准差 | 极差 | 最差相位 |
|---|---|---|---|---|
| 20d | 1.05（单相位） | — | — | 1.05 |
| **40d（当前生产）** | **1.41** | **0.14** | 0.24 | **1.33** |
| 60d | 1.39 | 0.16 | 0.31 | 1.22 |
| 80d | 1.63 | **0.49** | **0.95** | **1.09** |

三条判断：

1. **40d 与 60d 完全等价**（1.41 vs 1.39）——改 60d 没有任何收益，不予考虑。
2. **80d 均值高 0.22，但标准差是 40d 的 3.5 倍**。生产只跑**一个**相位，
   选 80d 等于在 [1.09, 2.04] 之间抽签，而不是稳定拿到 1.63。
3. **80d 最差相位（1.09）比 40d 最差相位（1.33）还差**。只看 offset=0 的
   1.75 就改参数，是把运气当能力。

20d 明显最差（1.05），直接排除。

---

## 二、方法

区间 2024-01-01 → 2026-08-14（634 交易日、3043 只股票、数据上限是 adj_factor 的末日），
策略 `lvr_vol_only`（单因子 `Volatility_20D`，权重冻结 v20261029a），
`top_n=10`、`industry-neutral`、`orthogonalized`，成本内建（佣金+印花税+滑点）。

每个 cadence 扫 3 个相位（`--rebalance-offset` = 0、1/3、2/3 周期），
共 10 次有效实验：

```
qp experiment run multifactor --strategy=lvr_vol_only \
  --start=2024-01-01 --end=2026-08-14 --top-n=10 \
  --rebalance=40 --rebalance-offset=13 --industry-neutral --orthogonalize
```

### ⚠️ 踩坑：`--rebalance 40`（空格）不生效

`experiment.py` 的参数解析器只认 `--rebalance=N` 等号形式（对比 `--start`/`--end`
两种形式都支持）。函数没有报错——`rebalance_freq` 悄悄回落到默认值 **20**。

第一次跑 20 和 60 时，两个实验的 description 都是 `rebalance=20d`、指标完全相同
（Sharpe 1.05 / 收益 57.37%），才发现跑的是同一个配置。**凡是 CLI 参数，跑完必须
核对实验 description 里的 rebalance 值，不能只看命令写对了。**

## 四、为什么方差随 cadence 放大（FACT → INFERENCE）

**FACT**：换手率随 cadence 单调下降（20d 1600% → 40d 960% → 60d 682% → 80d 521%），
交易成本同步下降（7.14% → 4.11% → 3.36% → 2.23%）。

**INFERENCE**：调仓次数越少，单次「调仓日落在哪个日历日」对总收益的权重越大。
2.6 年里 40d 调仓 16 次、80d 只有 8 次——样本量减半，方差必然放大。
这不是策略变差，是**分散度变低**。

**HYPOTHESIS**：80d 在 offset=0/26 的高收益可能来自「恰好躲过/踩中某几段趋势」。
未验证，也不建议继续验证——因为生产 anchor 是固定的（`2026-10-29`），
无法在未来选择相位，验证更多相位不改变「抽签」的本质。

## 五、生产影响（如果真改成 80d 会怎样）

- 当前 approved：`rebalance_cadence=trading_days`、`rebalance_days=40`、`rebalance_anchor=2026-10-29`
- 改 80d 后下一个调仓日约在 **2027-02 下旬**（现在持仓要拿 4 个月）
- 改 60d 约在 2027-01 中旬；保持 40d 约在 2026-12 下旬
- 改参数必须走 `qp strategy approve --params ... --from-experiment <id>` 重新冻结快照，
  不能手改 `data/strategy_registry.json`

**决策：不改。** 40 天保持，anchor 保持 `2026-10-29`。

## 六、本次顺带修复的缺陷（commit ea458c45）

扫相位时发现：同一 cadence 的 3 次实验（offset 0/13/26）**tags 与 description 完全一样**，
事后无法判断哪个是哪个相位 → 实验不可复现（违反「Everything is Experiment」的可审计要求）。

修复：`_record_experiment()` 接收 `rebalance_offset`，>0 时
description 追加 `, offset=Nd`、tags 追加 `offsetNd`；调用处传 `_bt_offset`。

验证：`--rebalance=40 --rebalance-offset=13` 产出的实验
`tags=['multifactor','top10','rebalance40d','offset13d']`、description 含 `offset=13d`。

## 七、下一步

cadence 这条路走不通，收益出口只剩两个：

1. **改 regime 敞口**（方案 A 的真正目标）：低波策略在熊市是 alpha 最强的时段，
   当前逻辑却给 10% 敞口。需要 2019-2026 分 regime walk-forward（本地数据只到 2024-01，
   这是硬约束，需先确认能否补历史数据）。
2. **换/加因子**：单因子 `Volatility_20D` 的 IC 0.0572、IC_IR 0.39，已经不差；
   要更高收益得提高单次收益而非次数。这是策略研究，不属于「修 bug」范畴。

## 八、复现

```bash
# 相位扫描（每个约 2.5 分钟）
for cad in 40 60 80; do
  for off in 0 $((cad/3)) $((cad*2/3)); do
    env -u PYTHONPATH .venv/bin/qp experiment run multifactor \
      --strategy=lvr_vol_only --start=2024-01-01 --end=2026-08-14 \
      --top-n=10 --rebalance=$cad --rebalance-offset=$off \
      --industry-neutral --orthogonalize
  done
done
```

注意：`--rebalance-offset=0` 时实验不会写 offset 标签（0 是默认值，省略即等价）。
